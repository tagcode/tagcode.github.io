    Uniform.Matrix.Video

    Video for calls, in pure C# with no native libraries: a VP8 decoder that turns the frames of a video call into pictures, and a VP8 encoder that makes frames of pictures. Nothing here knows about Matrix or the network: Uniform.Matrix.WebRtc puts the frames together from RTP, and Uniform.Matrix.Calls decodes them and gives the pictures to the app.

    Decoding

    Vp8Decoder decodes one frame at a time, in order, starting with a keyframe. Decode returns the picture of a shown frame, or null for a frame kept only as a reference, such as an alternate reference frame. A frame that cannot be decoded throws InvalidDataException; after that the decoder waits for the next keyframe.

    To decode a stream frame by frame:

    Vp8Decoder decoder = new();
foreach (byte[] frame in frames)
{
    if (decoder.Decode(frame) is VideoFrame picture) Show(picture);
}

    A VideoFrame is I420: full-size luma, and both chroma planes at half the width and height, rounded up, each tightly packed. CopyToBgra converts it to 32-bit BGRA for display, from the BT.601 limited range that WebRTC video uses; e.g. into a bitmap's rows:

    picture.CopyToBgra(pixels, stride);

    Encoding

    Vp8Encoder encodes pictures as VP8 frames, in pure C# too. A keyframe predicts each macroblock from its edges by DC; the inter frames between keyframes predict each from the previous picture at the same place, and skip those with nothing left to code, which for a camera is most of the picture. Residuals are transformed and quantized with one quantizer, and written with the default probabilities, without a loop filter. A keyframe comes every KeyframeInterval frames, and after RequestKeyframe, e.g. when the peer lost packets. Quantizer, 0 to 127, trades size for quality. The encoder reconstructs each frame with the decoder's own inverse transforms, so Reconstruction is the picture that decoders show; the tests check that bit for bit, and that Chromium decodes the frames.

    To encode a picture and send it in a call:

    Vp8Encoder encoder = new(quantizer: 40);
await connection.SendVideoAsync(encoder.Encode(picture));

    With MotionSearch, on by default, an inter macroblock may predict from a moved place: the neighbours' vectors and a diamond search of even whole pixels inside the frame are tried, and a vector is taken when it saves more than its bits. Even whole pixels keep chroma on whole pixels too, so predictions are plain copies.

    How the decoder is built

    The decoder is a port of the reference decoder in RFC 6386, Attachment One, with arrays and indices in place of pointers. Its constant tables in Vp8Tables.cs are generated from the reference sources. It works as the reference does, one macroblock row at a time:

    1. Modes and motion vectors, from the first partition.
    2. Coefficients, from the row's partition, dequantized.
    3. Prediction, intra or from a reference frame with the six-tap filter, plus the inverse transforms of the residual.
    4. The loop filter, one row behind, so that intra prediction sees unfiltered neighbours.

    Where the reference decoder and libvpx differ, it follows libvpx, which produced the test vectors' checksums. The tests decode all 17 VP8 test vectors of libvpx and compare the MD5 of every frame. The licence of the reference decoder and the test vectors is in THIRD-PARTY-NOTICES.md.

    On a desktop computer it decodes about 150 to 250 frames a second at 640×480.

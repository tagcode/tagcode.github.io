    Federation

    Federation is being built, behind Federation:Enabled. In Federation/:

    • ServerResolver finds other servers as the spec's server name resolution says: IP literals and names with a port directly, otherwise /.well-known/matrix/server delegation, then SRV records (_matrix-fed._tcp, then the deprecated _matrix._tcp), else port 8448. SrvLookup asks the system's name servers over UDP with the messages of DnsSrv; with an SRV record the connection goes to its target, while the Host header, and with it the TLS name, stays the server name.
    • FederationClient sends requests signed with FederationAuth (in Uniform.Matrix.Protocol.Server) as an X-Matrix authorization, through the same public-addresses-only handler as push gateways and URL previews.
    • RemoteServerKeys fetches other servers' keys from their /_matrix/key/v2/server, else from the key servers of Federation:TrustedKeyServers (whose own signature is checked too), accepts them only when every listed key signed the answer, and keeps the answer in ServerKeyResponses until valid_until_ts, at most a week. Old keys count for signatures too, and when nothing can be fetched the last answer is used even when expired. /_matrix/key/v2/query answers as a key server, each answer countersigned.
    • ServerAuthentication is middleware on endpoints marked RequireFederation(): it buffers the body, checks the signature over the raw request target, and gives the endpoint the origin with GetOrigin().

    FederationEndpoints serves /_matrix/key/v2/server, /_matrix/federation/v1/version, query/profile, make_join, send_join (v2) and send, and ProfileService asks other servers for their users' profiles.

    Joins: RoomService.JoinAsync sends joins of room IDs of other servers that are not here to RemoteJoins, which asks the room's server for a make_join template, signs it, sends it with send_join, fetches the signing keys of every sending server at once (RemoteServerKeys.PrefetchAsync: the key servers first, in batches, then each server, 20 at a time, each waiting at most Federation:KeyRequestTimeout), checks the content hash and signature of every returned event and the auth rules against each event's own auth events (AuthRules.CheckAuthChains), drops the events that fail, as other servers do, and stores the room with EventSender.StoreJoinedRoomAsync. The returned state and auth chain get negative stream positions, so they sort as history before the join and never count as new. On the resident side EventSender.MakeMembershipAsync builds the template and AcceptMembershipAsync checks the signed join (its ID, hash, origin and the auth rules) before storing it like a local event.

    Transactions: /send hands each PDU to RemoteEvents, which first asks the sending server for up to 20 events missing before it (get_missing_events) and accepts them oldest first, then hands the PDU to EventSender.AcceptEventAsync, which runs the checks on receipt; see below. When previous or auth events are still missing after that, RemoteEvents asks for the state before the event with /state_ids, fetches the events of it that are not here with /event, and stores them as history. FederationSender follows ServerStream and hands local users' events, remote joins this server accepted, and local users' device changes (m.device_list_update) to FederationQueue. The queue keeps one batch per destination (up to 50 PDUs and 100 EDUs per transaction) and retries failures with pauses doubling from 2 seconds to 5 minutes; a 4xx refusal other than 429 drops the batch. PDUs and the EDUs that matter later are also kept in the FederationOutbox table until sent, and FederationQueue.ResumeAsync queues them again at start; typing and presence stay in memory. RemoteActivity sends and receives typing (m.typing) and public read receipts (m.receipt); RemoteDevices handles keys across servers (user/keys/query, user/keys/claim, user/devices) and to-device messages (m.direct_to_device). Presence is not shared between servers yet.

    Invites of other servers' users: RemoteInvites signs the invite with EventSender.SignAsync (built and checked, not stored), sends it with invite v2 and the stripped room state from EventSender.InviteRoomStateAsync, checks that the invitee's server signed the same event, and stores it through AcceptEventAsync. Receiving invites is not there yet.

    Joins and leaves of other servers' users go through EventSender.MakeMembershipAsync and AcceptMembershipAsync; RemoteJoins.RejectInviteAsync rejects an invite to a room not here through the inviting server. RemoteJoins.ResolveAliasAsync asks query/directory for aliases of other servers. RoomHistory answers get_missing_events, backfill, event, state and state_ids for servers with a member in the room. Presence of local users goes out as m.presence EDUs from FederationSender; PresenceService.SetRemoteAsync keeps remote users' presence, which their server ends.

    Version 12 rooms are created by EventSender.CreateHashedRoomAsync, which signs the create event before the room row exists, as the room ID is its hash. Version 12 is the default for new rooms. Their IDs name no server, so joining one by ID needs via servers, which both clients send.

    Sliding sync (SlidingSyncService, POST /_matrix/client/unstable/org.matrix.simplified_msc3575/sync) builds rooms with SyncService, from the start for rooms a connection has not had and since its position for the others, and reshapes them into lists, room subscriptions and the to-device, e2ee, account data, receipts and typing extensions. Connections live in memory; an unknown position gets M_UNKNOWN_POS.

    Server:TrustedProxies turns on ASP.NET Core's forwarded headers for those addresses only.

    Room summaries (/v1/room_summary and the unstable im.nheko.summary paths) and space hierarchies (/v1/rooms/{roomId}/hierarchy, and /_matrix/federation/v1/hierarchy for other servers; rooms not here are asked from servers in them, the via servers a client gives, the alias's servers or the room ID's server, through federation hierarchy) come from DirectoryService, shown to members and invitees, and to anyone for public, knockable or world-readable rooms. SyncService answers /v1/rooms/{roomId}/relations (found by the related event's ID in the stored JSON, then checked), /v1/rooms/{roomId}/threads and timestamp_to_event; relations are also kept in the EventRelations table, from which thread roots get their m.thread summary in unsigned. Reports of content, rooms and users are kept by ReportService for the dashboard's review list, and logged.

    Media of other servers: MediaService fetches it on first use with FederationClient.DownloadAsync from /_matrix/federation/v1/media/download (a multipart/mixed answer: metadata, then the file; redirects to elsewhere are not followed), falling back to the legacy unsigned /_matrix/media/v3/download of older servers, and keeps it under an ID of its own in RemoteMedia; thumbnails of it are made here. The federation media endpoints serve local media the same way. The unauthenticated legacy reads, when turned on, serve local media only, so nobody without an account can make the server fetch from others.

    FederationSender keeps how far it got in FederationProgress, so events stored just before a stop are still sent after the restart.

    Older clients use r0 paths and unstable key backup and cross-signing paths; LegacyPaths maps them to v3 before routing. Requests no endpoint knows are logged with method and path, without the query.

    Room version 12 (RoomVersion.V12, RoomIdIsCreateHash): the room ID is ! and the create event's hash, the create event has no room_id and is left out of auth_events, and the creators (the sender and additional_creators, see AuthRules.Creators) have unlimited power and cannot be listed in power levels. Such rooms can be joined through via servers, since their IDs name no server; creating them here is refused until room creation builds the create event before the room's row. FederationTests run two servers in memory whose federation clients reach each other through a test handler.

    HTTPS comes from TlsCertificate (in Http/), which reads the PEM files of Tls:*, sends the intermediates with the certificate (other servers check the chain) and reads the files again within a minute of a renewal.

    Receiving events, forks and state resolution

    EventSender.AcceptEventAsync (in EventSender.Remote.cs) checks a received event in the spec's order:

    1. Its content hash, and the sender server's signature.
    2. Its own auth events: all stored here, of this room, each once, and of the kinds its type needs; the auth rules must allow it against them.
    3. The state before it: the state after each of its previous events, merged when they differ, with the state its server reported for previous events not here. The auth rules must allow it against that state. Events failing 1–3 are rejected and not stored.
    4. The room's current state: when that no longer allows the event, as when its sender was banned meanwhile on another server, the event is stored soft-failed. Soft-failed events stay in the room graph but are not shown and not built on; a global query filter on EventRow.SoftFailed hides them, and the few queries that need them ignore it.

    Each event keeps the state groups before and after it (StateGroupBefore, StateGroup); /state_ids answers with the state before, as other servers expect. When the room has several forward extremities, its current state is merged from their states by StateResolution in Uniform.Matrix.Protocol.Server. Sync sends state that changed without the timeline showing it, as after such a merge, in the room's state.

    Room ACLs (m.room.server_acl) are checked by RoomAcls for the requesting server: joins, leaves, invites and history are refused, and its events, typing and receipts in /send are dropped for rooms whose ACL denies it.
